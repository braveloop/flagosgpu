## 1. 范围与结论

本目录收录 10 份已验证的论文 PDF：9 篇正式会议论文、1 篇明确标为预印本。正文核对以本地 PDF 的核心方法、实验和相关附录为准，不声称逐图逐表都已复核。ASPLOS、OSDI、PPoPP 条目是已确认的正式论文；MLSys 单列为相关系统会议；ICLR 只标正式会议论文，本轮没有核验其 CCF 类别。“CCFA”目录名不代表目录内每篇都已核验为 CCF-A。

对比赛最有用的不是论文里的峰值数字，而是六类可检验机制：保序采样后处理、radix payload 缩减、数据分布驱动的 pass 消除、GQA KV 复用与负载分配、混合 Prefill/Decode 共驻，以及局部 producer-consumer 融合。本索引记录论文研究时的判断；int32 radix index 已在后续完成租赁 C500 预验证，当前成果见 [S03](../docs/S03-C500排序索引优化.md)，后续优先级以[总计划](../DETAILED_OPTIMIZATION_PLAN.md)为准，其余方向仍须逐项实现和验证。

论文结果来自 NVIDIA A100/H100/B200、AMD MI250 等不同硬件和不同模型、精度、batch、采样设置，不能外推到 BI-V150 或 C500。未来实现仍须遵守比赛边界：不通过改超参开启量化或投机采样，不改 benchmark 或官方测试参数，不以仅切后端、删除选择逻辑或合并新框架作为优化。

## 3. 逐篇方法、实验条件与迁移边界

### 3.1 FlashInfer：格式、tile 与动态规划是三层机制

FlashInfer 用 ragged tensor 存放不等长的 Q/O，并把 page table、radix tree 等不规则 KV 访问统一表达成 BSR。这里的“块稀疏”首先是存储和访问组织方式，不表示可以丢弃原本应该参与 softmax 的注意力连接。不同共享前缀还可拆成多个可组合格式，使共享部分采用更大的 query-row block 复用 KV，而独有部分保持细粒度访问。

计算模板根据 query 长度、GQA 分组、head dimension、寄存器和 shared-memory 限制选择 Q/KV tile。短 query 可走与大 query 不同的计算路径。对于 Hopper，TMA 只用于连续 KV；paged 等非仿射 KV 地址仍回退到 Ampere 风格异步拷贝，不能假设 paged KV 可直接用 TMA。

运行时 planner 用

\[
\operatorname{cost}(l_q,l_{kv})=\alpha l_q+\beta l_{kv}
\]

估算 tile 代价，把较长工作优先分给当前累计代价较低的 CTA。它是 CPU 端的计划式贪心分配，不是 LeanAttention 的静态 Stream-K 区间划分。

FlashInfer 把 plan 与 run 分离：planner 每个 generation step 生成 work queue 和 partial-output 映射，复制到固定 workspace；attention/contraction 使用固定 grid 和稳定地址以支持图执行。计划只有在相关 shape 与序列元数据一致时才能跨层复用，不能仅因为 MiniCPM5-2B 有 42 层就无条件共享。固定 partial 合并顺序有利于相同配置重复执行的确定性，但不证明与当前 vendor kernel 逐位相同，也不保证 batch 组成改变后仍逐位一致。

原实验使用 FP16、A100 40GB/H100 80GB、CUDA 12.4 和 PyTorch 2.4。论文中 28%—30% 的长上下文 ITL 改善来自 StreamingLLM/Vicuna-13B 的定制 RoPE 与 sparse-window 路径，不适用于本题普通全 KV attention；prefix reuse 和并行生成结果也不能成为改变官方配置的理由。可迁移的是 shape-aware tile、GQA KV 复用和有条件的轻量 metadata 复用，而不是切换到 FlashInfer 后端。

### 3.2 LeanAttention：Stream-K 划分与在线 softmax 合并

LeanAttention 把 batch、head 和 context 展开成连续 LeanTile 工作区间，再按硬件相关的 CTA 数量做 Stream-K 式静态分配。一个逻辑 attention 可能被多个 CTA 分片，每个分片保留在线 softmax 摘要。设两段状态为 \((m_a,l_a,U_a)\) 和 \((m_b,l_b,U_b)\)，其中 \(m\) 是局部最大值、\(l\) 是指数和、\(U\) 是未归一化的加权值和，则

\[
\begin{aligned}
m &= \max(m_a,m_b),\\
l &= e^{m_a-m}l_a+e^{m_b-m}l_b,\\
U &= e^{m_a-m}U_a+e^{m_b-m}U_b,\\
O &= U/l.
\end{aligned}
\]

该式在实数数学上保持 softmax 语义，但不等于浮点逐位相同。空块或全部 masked 的状态还需要显式分支，不能无条件计算 \(\exp(-\infty-(-\infty))\)。分片完成后，一个 host CTA 按规定顺序读取其他 CTA 写到 global memory 的 partial，并在同一 kernel 内做 fixup；因此它减少额外 kernel launch，却不是“没有中间全局访存”。

LeanTile 大小、CTA 数和 grid 都是硬件与 shape 相关选择。短 context 或少 head 时可以缩小 grid，不要求所有 shape 铺满全部 SM；split 增多通常会增加 partial workspace、同步和归并成本，Q 或边界数据是否发生重复读取则取决于具体划分与布局，不能外推为全部 KV 必然重复读取。论文的 dense/ragged 布局也不自动兼容本项目的 paged KV。

实验基线包括 FlashAttention 2.5.6 和 FlashInfer 0.1.6；FlashInfer 对比使用旧 single-batch API，并通过放大 head 数模拟 batch。原结果不能解释为胜过当前 FlashInfer 或比赛 vendor backend。对本项目有用的是把静态工作划分、partial 成本和尾部空闲作为独立变量，而不是照搬 A100 tile 常数。

### 3.3 POD-Attention：在同一 kernel 中共驻两类负载

POD-Attention 利用的是计算密集的 Prefill 与访存密集的 Decode 之间的互补，而不是笼统的“矩阵资源与向量资源互补”。kernel 启动后读取 SMID，并通过每个 SM 的原子票据决定 CTA 执行 Prefill 还是 Decode，使两类 CTA 在同一 SM 共驻。

其具体机制还包括：把 Decode 的 query-sequence-length tile 缩到 16，减少零填充造成的无效 Tensor Core 运算；根据负载采用 2 或 4 CTA/SM；让多个 warp 作为 virtual Decode CTA 共享一个物理 CTA 的资源；限制 chunked-Prefill 的 KV split 数，避免过多重复读取与 Decode 争用带宽。persistent kernel 仍需 SM-aware 分配，并非“改成 persistent”就自动得到 POD，也不是开两个 CUDA stream。

这些选择来自 A100/CUTLASS 条件，不能写成 C500 或 BI-V150 的固定常数。实验使用 A100 80GB，Yi-6B 单卡，Llama-2-7B 和 Llama-3-8B 双卡，并与 FlashAttention 2.6.1、Sarathi/vLLM 路径比较。迁移前必须先证明正式 workload 中 mixed Prefill/Decode 的时间占比、共驻资源余量，以及目标平台的 SM 身份、原子操作和 forward-progress 能力。

### 3.4 vAttention：连续虚拟地址与按需物理映射

vAttention 的“连续”指连续虚拟地址，不要求物理页连续。它预留足以覆盖最大 batch 和 context 的 KV 虚拟地址空间，再按请求已到达的长度映射物理页。令 \(L\) 为最大 context，\(H\) 为单卡 KV head 数，\(D\) 为 head dimension，\(P\) 为单元素字节数（BF16 为 2），\(B\) 为最大并发请求数，\(N_{layer}\) 为该 worker 上的层数。单请求、单层、单个 K 或 V 的最大大小为

\[
S=L\times H\times D\times P\quad\text{bytes},
\]

单个 K 或 V buffer 的预留虚拟地址大小为 \(B S\)，所有层的 K/V 合计为 \(2N_{layer}BS\)。这些是虚拟地址预留量，不是已经映射的物理显存。

对 MiniCPM5-2B，\(H=2,D=128,P=2\)，所以单层单个 K 每 token 为 512B；\(L=131072\) 时为每请求、每层、单个 K 64MiB。42 层 K/V 合计仍是每 token 43008B。实际物理显存还取决于已映射页面、预分配和碎片，不能用最大虚拟地址预留量替代。

实现使用 virtual KV tensor、稳定 request ID 和 `cache_batch_idx` 映射。下一轮 Decode 所需页数可预测，后台线程可以提前映射；结束请求的页面延迟回收，并可先为后继请求准备映射，以隐藏 VMM 系统调用延迟。

标准 CUDA VMM 在论文中以 2MB 粒度工作；64/128/256KB page-group 依赖作者对 NVIDIA 开源驱动接口的扩展，不是 Python allocator 开关。实验主要在 A100 80GB 上运行 Yi-6B、Llama-3-8B、Yi-34B，H100 用于演示 FlashAttention-3 的移植；不同 backend 还分别选择 block size，观察到的差异不能全部归因于虚拟内存。

该方向不是规则上当然“违规”，但目前没有已验证的 MetaX/BI VMM 接口，且需要驱动、allocator 与 KV cache 管理重构，远超近期局部修改。近期价值是测量并优化块表准备、地址计算、metadata 和 cache 行为，而不是替换整套 KV 管理。

### 3.5 Mirage：多层 µGraph 搜索不等于 BF16 等价证明

Mirage 的 µGraph 在 kernel、thread block、thread 三层共同表示代数变换、分块、存储和调度。生成器在 kernel/block 层枚举并剪枝，在 thread 层用规则构造；验证之后还优化 layout、同步顺序和内存分配。它探索的不只是相邻算子拼接。

RMSNorm→MatMul 案例会把归一化除法后移，并行进行平方和与 MatMul 的累积。这改变了实际浮点运算次序和 BF16 中间舍入，不能因代数上可交换就直接用于本题。GatedMLP 案例的原方法是让两次输入投影 MatMul 并行，并在同一 block graph 中融合 SiLU 与 elementwise Mul；它没有把 down projection 一并融合。后文提出的 `SiLU(gate)×up→down` 是本项目的新推论，不是 Mirage 原方法。

有限域随机 verifier 只适用于论文定义的 LAX 程序：算子限于 multi-linear、division 和 exp，且每条 input-output path 至多包含一次 exp，并非任意非线性程序。§7 对 ReLU 等非 LAX 程序另用依赖用户提供数学性质的 solver。

论文理论说明，多次有限域随机测试可降低等价性误判概率；但 §7 的实现使用 \(p=227,q=113\)，只执行一次随机测试，再以浮点测试过滤明显误差。这不是任意低误判保证，更不是 BF16 逐位证明。

实验在 A100/H100 上评估半精度 tensor programs，部分 shape 仍会退化，因此“融合必然更快”不成立。本项目只借鉴小范围数据流、layout 和同步搜索；任何代数重排都必须重新通过当前模型的数值与采样验收，不能引入整个 superoptimizer。

### 3.6 NanoFlow：跨资源流水与其成本模型前提

NanoFlow 的成本模型面向尽可能大的 dense token batch、充分请求供给和典型大模型。近似式

\[
T_{mem}\approx \frac{\text{MemSize}}{\text{MemBW}}
\]

隐含权重/缓存访问和带宽利用假设，不能直接用于本题 batch 64 的单卡 2B 模型。nano-batch 保留原算子语义，但切分 batch，让计算、访存、通信型操作交叠；代价是权重重复加载以及小 GEMM 效率下降。

搜索分两阶段。Stage I 暂不考虑并发干扰，选择 nano-operation 数量、batch 划分与依赖顺序，实际寻找可行的高质量解以控制时间；Stage II 固定该划分和依赖，用实测干扰映射选择资源份额与 kernel 配置。论文中的 \(R\) 由 GEMM 性能定义，是资源份额的代理量，不是可独立分配的真实算力或显存带宽；pairwise 干扰模型推广到三类操作同时重叠也有假设，因此不是硬件全局最优证明。

运行时使用多个 CUDA stream 和 event，与 POD-Attention 的同 kernel CTA 共驻不同。主要实验是 8×A100 80GB、FP16、Llama-2-70B，并扩展到其他模型；低请求率下延迟可能略高。异步 EOS 会在检测完成前多执行一轮 token，可能多消耗 RNG，本题不能直接采用；SSD/CPU 多轮 KV 管理也不是近期方向。

### 3.7 ThunderKittens：worker、CTA 与 grid 三层抽象

ThunderKittens 在 worker 层以 16×16 tile 为基本单位管理寄存器和 shared-memory 数据。不同 dtype 具有不同 packed 表示和硬件约束；shared-memory layout 在 32/64/128 字节边界的 swizzle 中选择，以降低 bank conflict。图 4 同时说明某些 tile/访问模式的冲突不可避免，因此不能写成 swizzle 消除了所有冲突。

CTA 层用 LCSF（load/compute/store/finish）模板组织 producer-consumer、多 stage buffer、异步拷贝和 barrier。增加 stage 可隐藏搬运，但也占用更多 shared memory 和寄存器；单个 GEMM 表格不能证明 stage 越多越快。grid 层用 persistent CTA 连续领取任务，load/store worker 可预取下一任务以减少 setup/tear-down；任务排列还会改变 L2 复用。Table 3 的 consumed HBM GB/s 在更优 block order 下下降而 TFLOPS 上升，含义是 L2 复用减少了 HBM 取数，不是“HBM 利用率下降导致变慢”。

主实验使用 H100 SXM、CUDA 12.6；附录还覆盖 RTX 4090 和 Apple M2 Pro，所以它并非绝对 NVIDIA-only，但没有 C500/BI-V150 适配证据。相对 FlashAttention-3 的显著 attention 数字主要来自 backward；linear attention 和 SSM 的收益也不对应本题标准 softmax inference。

可迁移推论是把 CTA/task 顺序和 GQA KV 的 L2 复用作为 Attention 内部子实验，独立测量重复读取与尾部空闲。复用思想不等于仅切换一个现成排布就构成比赛创新。

### 3.8 MPK：SM 级任务图与事件驱动 mega-kernel

MPK 的 tGraph 把算子拆成输出区域互不重叠的 SM 级任务，并依据 producer/consumer 区域交集建立事件。event fusion、normalization 和 linearization 用于压缩同步与图表示成本。worker/scheduler 运行时按事件推进任务：JIT 只在依赖满足后动态分发易失衡任务，AOT 则把固定任务预先放入 worker queue、待事件满足后执行；这里不是 Python JIT 与离线编译的区别。

MPK 的 paged shared-memory 是片上共享存储的页，不是 paged KV cache。跨任务 pipeline 只有在前一任务已经发完自身拷贝指令且共享页足够时，才预取下一任务。单 mega-kernel 可消除重复 kernel launch，但任务队列、事件、信号量以及跨任务/跨 SM 中间数据仍可能访问 global memory。实现中的 task description 为 352B，并存放在 device-memory queue；实验还保留 4 个 scheduler SM、共 16 个 scheduler warp，因此调度不是零成本。

实验覆盖 A100/H100/B200，离线 batch 为 1—16，prompt 为 64、输出 1024；artifact 明确使用 greedy decoding。这与本题 temperature=1 的随机采样和并发 64 不同。局部 Norm→QKV 等融合只是本文从任务图机制得到的工程推论，不是 MPK 原机制的等价概括，更不能据此替换整个执行框架。

### 3.9 MetaAttention：正式版本的两层搜索与跨后端边界

MetaAttention 把 attention 的固定骨架与 customizable function 分开，支持 parallel/recurrent pattern。在线归一化所需的状态、rescale、prologue/forward/epilogue 必须由模板与用户正确定义；框架不会自动证明任意 attention 修改在数学或浮点上等价。

`IntermediateTensor` 记录 tile shape、memory location 和 pipeline stage，`DeviceConfig` 描述基础 tile 与存储容量等硬件约束。外层枚举 output tile 并向计算图传播；内层先尝试更高的存储层级，超出容量时逐级 demote，再对可行计划做 profile 选择。这是约束搜索与实测择优，不是遍历所有 tile/存储组合后的全局最优保证。Table 4 的秒级 scheduling/search 时间也不是 kernel latency。

正式实验使用 H100 SXM5（CUDA 12.4、Triton 2.3.1）和 MI250（ROCm 6.2.4、Triton 3.1.0）；支持讨论中的 MI300X 不是实测平台。主要 operator shape 为 batch 1/8、sequence 2K/4K/8K，端到端实验基于 Transformers、16K input、FP16。最高 10.4× 来自某些现有基线不支持的变体，平均约 1.4× 的端到端结果也不能外推到本题标准 GQA/BF16。

可迁移的是用目标硬件资源约束缩小 tile/stage/layout 搜索空间，而不是引入 MetaAttention 框架、改变模型机制或搬用其 H100/MI250 参数。

### 3.10 Qrita v2：pivot 搜索的 guard、ties 与浮点边界

Qrita 先采样一块 logits 估计均值和方差，通过 lookup 阈值形成截断候选集。top-k 检查候选数量是否足够，top-p 检查候选概率质量是否覆盖目标；guard 不满足时回退到完整集合搜索。因此它不是依据高斯假设无保证地删除 token。

搜索阶段在同一轮扫描中评估三个 pivot，把区间四分，同时追踪边界最小值及重复次数。对有限 logits 序列 \((z_i)\) 和合法的 \(k\)，按搜索集合中的 token 位置计数，令

\[
A_\tau=\{i:z_i>\tau\},\quad N_\tau=|A_\tau|,\quad
d=\min_{i\in A_\tau}z_i,\quad N_d=|\{i:z_i=d\}|.
\]

当 \(A_\tau\neq\varnothing\)、\(N_\tau\ge k\) 且 \(N_\tau-N_d<k\) 时，边界重复值需要保留

\[
N_{keep}=k-(N_\tau-N_d)
\]

个：保留所有 \(z>d\)，再按原 token 次序保留所需数量的 \(z=d\)。这是找到合法边界时的数学条件；迭代上限和特殊值仍需单独处理，不是当前实现或性能收益。该 duplicate handling 在论文定义下保持确定性，但当前 fallback top-k 使用 strict `< kth` 掩码并保留全部 threshold ties，两者未必同语义。tiered block size 则分别适配完整词表和截断集合。

这里有三类不能用“数学 exact”掩盖的实现差异：

1. 论文脚注明确指出，未排序 logits 上的 softmax 可能因浮点非结合性而与排序后的 softmax 不同。

2. top-p 的累计顺序、边界比较与 ties 处理必须和当前 fallback 单独比较。

3. 伪码形式 `Z + (1-M) * (-inf)` 不能按 IEEE 浮点字面实现，因为 `0 * (-inf)` 会产生 NaN；实现应使用条件 mask。正文与附录的 safety margin 写法也不能未经核对拼成一个可执行公式。

四分搜索并非所有情况都更快：Table 3 的 truncation-hit 中四分为 1.308ms、二分为 1.281ms；miss 时四分优势更明显。论文的 1.41× 来自特定 GPT-OSS-20B workload，“跳过 sampling”只是不可用于本题的理论对照。

只读上游 vLLM 已引用并实现 Qrita，因此近期方向不是“引入 Qrita”。如果继续研究，必须是面向 MetaX 编译器的实质分解或重写，并先解决与当前 fallback 的浮点、ties、token 次序和 RNG 一致性；直接启用已有分支不构成新优化。

补充但不计入上述 10 份：**FlashAttention-T** 是 PPoPP 2026 正式论文（[会议页](https://ppopp26.sigplan.org/details/PPoPP-2026-papers/15/FlashAttention-T-Towards-Fully-Tensorized-Attention-by-Exploiting-Tensor-Vector-Para)，DOI [10.1145/3774934.3786425](https://doi.org/10.1145/3774934.3786425)）。本轮只有正式摘要证据，因此只记录“把部分 softmax primitive 放到空闲 tensor unit、按架构调度 tensor/vector 并行”的线索，不补写未经全文核验的算法或数字。

## 4. 六个工程方向与条件优先级

### 4.1 近期低风险：保序 top-p 后处理融合

第一版保留现有 sort、top-k mask、softmax、cumsum 及返回 alias，只融合后续比较、末位保留、masked fill 和 scatter，目标是减少临时张量和 launch，不引入 Qrita 阈值法。投入前先用 profile 确认这些中间步骤没有已被当前 compile 路径融合，否则源码层合并不代表运行时工作减少。

真实落点是 `vllm-plugin-FL/vllm_fl/dispatch/backends/vendor/metax/patches/topk_topp_sampler.py`。`1-p` 的 dtype/promotion、`<=` 边界、NaN/Inf 比较、`-inf` 写入和输出 alias 必须匹配当前实现，不能把所有输入擅自强转 FP32；后续 exponential noise、生成器调用顺序与 RNG 消耗保持不变。

compile/unsupported 检查必须在任何原地 logits 写入前完成；不能先部分改写输入，再捕获运行失败并用受污染的 logits 执行 fallback。不支持的 dtype/shape 或编译失败必须从未修改输入完整回退。同 logits/seed 的 token、RNG 状态与 logprobs 差分是正式门槛之一，但不自动证明所有 shape 都正确。

### 4.2 近期候选：radix 内部 int32 index

在 `FlagGems/src/flag_gems/ops/sort.py` 中，行内元素数满足 `n < 2^30` 时，可以研究用 int32 携带内部稳定索引，最终 API 输出前恢复 int64。FP32 value 加 index 的单元素 payload 可由 12B 降为 8B，但这不是整个 sort 或端到端流量减少三分之一。

`n < 2^30` 只证明行内 index 范围，不证明 `pid_m * n`、stride 或总元素地址偏移不会溢出；地址计算必须保持足够宽度。最终转换成本要计入端到端，且与其他 sort 变化分开消融。

### 4.3 先测分布：radix 整 pass 恒等消除

若同一行的某个 digit 只有一个非空桶，则该稳定 radix pass 不改变排列，可以研究跳过 payload 搬运。但必须先在真实采样输入上统计这种 pass 的频率，不能从 BF16 模型或一次 microbenchmark 推断它常见。

一个反例是：BF16 精确扩展成 FP32 后低 16 位通常为 0，但负数经过排序 key 的反码变换后低位可全为 1，而正数仍为 0；正负混合行在这些 digit 上至少落入两个桶，因此“BF16 输入必有恒等低位 pass”不成立。

实现必须维护每行 device-side buffer parity，让全部 CTA 对是否执行 pass 作一致决策，并正确覆盖 index 初始化、所有 pass 都跳过、最终 active buffer 选择。不能让 kernel 提前 return 而 host 仍照常交换 buffer；各行 parity 不同时还可能需要最终 buffer 归一化拷贝。device 端提前退出也不会自动消除 host 发起的 sweep launch 或 `status.zero_`，这些固定成本都要计入净收益。

所有 pass 都跳过时也不能直接返回输入并让 sort 输出意外 alias 原输入，必须保持原 API 的输出所有权契约。重复 digit pass 的消除还需要独立证明，不能仅由单次 histogram 推出。

### 4.4 高潜力但需新 profile：GQA Attention 数据流与调度

把 Attention 研究拆成三个可独立消融的维度：

- MiniCPM5-2B 的 GQA=8 是否能让同组 query head 共享 KV tile，减少重复读取。

- 静态 Stream-K 区间与 planner 式工作分配如何影响长短序列不均衡、partial workspace、同步和尾部空闲。

- CTA/task 顺序、L2 复用以及 tile/stage 资源选择能否在真实 backend 上改善带宽或占用率。

不能把 FlashInfer、LeanAttention、ThunderKittens 的不同机制统称成一个 persistent queue，也不能混淆 request、KV head 和 query-head group 的映射。split 带来的 partial workspace、同步和归并成本必须完整计量；潜在重复访存要按具体布局和访问轨迹确认。固定 merge 顺序不等于与旧实现逐位一致。

C500 的外部 vendor kernel 核心不在允许仓库内，但这不表示只能新写完整 kernel：允许范围内的 wrapper、KV 准备、layout、metadata 和 scoped kernel 都可研究，前提是形成实质改进并保留现 backend/fallback，而不是切后端。BI-V150 同样先确认正式环境真实调用路径。

### 4.5 条件成熟后：POD 式同 kernel 融合

只有 E2 后的新分相 profile 证明正式 workload 有足够 mixed Prefill/Decode 窗口，并确认平台共驻、原子和 forward-progress 能力，才投入同 kernel CTA 协作。目标是计算密集 Prefill 与访存密集 Decode 的互补，不能用两个 stream 或修改 scheduler/官方参数代替。

纯 Prefill、纯 Decode、尾批和不支持 shape 必须保留原路径。QSL、CTA/SM、virtual CTA 与 split 上限都是待目标平台验证的变量，不沿用 A100 常数。

### 4.6 探索项：局部 producer-consumer 融合

Mirage、MPK 和 NanoFlow 只提供方法启发。先用真实调用链和 profile 确认真正活跃、相邻且中间往返显著的算子，再研究单条局部链；不能修改未激活的 FlagGems 同名算子，也不能以引入新执行框架代替局部实现。

Norm→QKV 与 `SiLU(gate)×up→down` 是两个不同风险、不同实现的假设，必须独立消融。Mirage 原 GatedMLP 只把两次输入投影与 SiLU/Mul 放进同一 block graph；继续融合 down projection 是本项目推论。任何实现都必须保留 BF16 中间舍入、epsilon、实际累积 dtype、stride、alias 和原地 residual 语义。框架级 nano-batch 与异步 EOS 不列为近期实现。

## 5. 验收要求

文献中的数学等价、同一实现的重复执行确定性、与当前实现的逐位或采样一致性是三种不同结论，不能互相替代。本轮只修订文档；以下是未来方向进入实现后必须逐项满足的门槛。

| 范围 | 正确性与边界检查 | 性能与保留条件 |
|---|---|---|
| sort | 升/降序、ties、`±0`、`±Inf`、NaN、非连续输入、buffer parity、所有 pass 跳过、宽地址；最终 index dtype 与稳定次序不变 | 先统计真实 digit 分布；int32、pass skip 与已有优化分别做原版→单项→恢复原版 |
| sampling | top-k only、top-p only、组合、输入 dtype、`1-p` promotion、`<=` 边界、NaN/Inf、末位保留、alias；同 logits/seed 核对 token、RNG 状态和 logprobs | 证明目标临时张量/launch 消失；MetaX 编译失败或未知 shape 从未改写输入正确 fallback |
| attention | 尾块、全部 masked、混合长度、paged KV、GQA head 映射、partial merge、纯/混合相位与 fallback | 用 E2 后的新分相 profile 决定投入；GQA 复用、负载分配、L2 顺序、POD 分别消融 |
| 局部融合 | BF16 中间舍入、FP32/实际累积 dtype、epsilon、stride、alias、原地 residual、未支持 shape | 每条链独立验证；中间访存或 launch 按设计消失且端到端收益超过噪声 |

任何未来实现都必须先通过确定性短、长和混合 prompt，再运行完整 MATH-500 Level 3，保持 `accuracy >= 0.95`；正式性能仍按 BI-V150 与 C500 的 4K/1K、16K/1K 官方四轮流程执行，丢弃首轮并统计后三轮，要求全部请求成功、Mean TTFT 合规、收益超过实测波动。不得修改 benchmark、官方输入或服务参数。

论文数字、旧 profiler self-time 和 microbenchmark 不能代替当前端到端证据。本轮没有运行项目、模型、GPU、Accuracy 或 benchmark，也没有产生任何性能收益结论。
