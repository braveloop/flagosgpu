## 1. 比赛规则与执行边界

[官方规则] [赛题数据接口](https://flagos.io/flagos/api/v1/races/539vlt2p)的中文数据在 2026-10-01 复核时，`metadata.last_updated` 仍为 `2026-09-22T15:32:53`。字段 `race_start` 写 2026-09-11，正文写开发与提交阶段从 2026-09-21 开始，起点仍需组委会确认；作品提交截止为 2026-11-20 23:59（UTC+8）。日期口径不能由个人安排代替官方答复。

[官方规则] 目标是在天数 BI-V150 和沐曦 C500 64GB 上提升 MiniCPM5-2B 的 `total tokens/s`，同时保持完整 MATH-500 Level 3 精度不低于 `0.95`，并满足 TTFT 限制。允许有实质开发量的显存管理、动态批处理、算子融合、内核重写与自研量化；优化应尽量泛化到正式场景以外的形状。报告中的每项策略必须存在于最终提交代码并实际启用。

[官方规则] 不得改动正式 `vllm serve` 参数、模型语义、采样行为、benchmark 脚本、prompt 或输出长度；不能仅切到更快的现成后端、开启现成量化或投机采样、删除主要选择逻辑，或直接合并新分支取得收益。4K 与 16K 都要验证，不能以一个场景的收益掩盖另一场景的退化。

[待平台验证] 本机的 NVIDIA 显卡不运行本项目。租赁 C500 的结果只用于诊断和预验证，不能称为组委会认可环境的正式成绩；BI-V150 与组委会认可 C500 的精度、双场景性能和阶段验收仍未完成。当前学习结果只以官方公布的 A0 与当前改进 B1 对照，具体数值统一见 S02。

## 2. 模型与真实调用链

[源码事实] [MiniCPM5-2B 配置](https://modelscope.cn/models/OpenBMB/MiniCPM5-2B/resolve/master/config.json)声明 `LlamaForCausalLM`、BF16、42 层、hidden size 2048、intermediate size 6144、16 个 Query Head、2 个 KV Head、head dim 128、最大上下文 131072。GQA 的 Query/KV Head 比是 8:1。固定开发起点分别为 `vllm-plugin-FL@13eb9be69ecc5b5ca4f79c44e9ee40081eaa1bf0`、`FlagGems@a7620cc191a0b42e040194622c5758b22a7a25dc` 和只读参考 `vllm@ee0da84ab9e04ac7610e28580af62c365e898389`；它们是起点，不等于此后每次实验的实际 HEAD。当前 plugin 开发分支已有 M1 提交 `47882ba2585dafdec92f06aff8ceb8af1de54630`。

一次请求在本项目中的关键路径是：

```text
OpenAI API → vLLM scheduler / model runner
→ registry.py:LlamaForCausalLM → LlamaModel
→ 42 × LlamaDecoderLayer
   → input RMSNorm → QKV projection → RoPE → Attention → O projection
   → post-attention RMSNorm → Gate/Up projection → SiLU×gate → Down projection
→ final RMSNorm → lm_head / LogitsProcessor → logits
→ 引擎采样与下一轮 Decode
```

[源码事实] `vllm/vllm/model_executor/layers/attention/attention.py:Attention.forward@ee0da84` 根据 backend 的 `forward_includes_kv_cache_update` 判断是否独立写入 KV Cache，再进入对应的 Attention 实现。采样和流式响应在模型类之外；模型配置、源码中存在某个 backend，均不能单独证明正式运行命中了该 kernel。正式验证须记录实际 import 路径、backend、编译实现和设备 kernel。

[源码事实] BI-V150 的固定配置 `vllm-plugin-FL/vllm_fl/dispatch/config/iluvatar.yaml@13eb9be` 优先经过 FlagGems selector，但 `vllm_fl/dispatch/backends/flaggems/flaggems.py` 在未启用 `VLLM_FL_USE_FLAGGEMS_ATTN` 时返回 `TRITON_ATTN`，并不自动命中 `AttentionFLBackend`。只有官方运行确认命中该实现，才调查 C0 或其 FlagGems Attention 候选；不得为触发候选而私自切换后端。

[源码事实] C500 的 `metax.yaml@13eb9be` 为 Attention 选择 `vendor.metax`，对应 `vllm-plugin-FL/vllm_fl/dispatch/backends/vendor/metax/impl/attention/flash_attn.py` 的 `FlashAttentionMetadataBuilder` 与 `FlashAttentionImpl`；RMSNorm、SiLU 和 RoPE 仍优先 FlagGems。`USE_C_EXTENSION`、`flag_gems.config.has_c_extension`、`use_c_extension` 和实际 dispatch 共同决定能否把 `ops/attention.py → flash_api.py` 当成运行路径。

[源码事实] `AsyncSchedulerFL` 也不是默认必经节点：`WorkerFL.__init__` 仅在 `num_speculative_tokens == 1` 且 `async_scheduling` 开启时改用它。正式命令未启用投机采样，因此任何调度或后端优化都要先确认实际调用链。现有通用测试也不自动覆盖本模型的 Q16/KV2、BF16、长 KV、原地 RoPE、Norm epsilon 与 SiLU 切片 stride；候选的差分与端到端验收见详细优化方案。

## 3. 官方复现命令

[官方规则] 以下命令保留赛题原始参数。服务 shell 的工作目录为 `/workspace`，只对该 shell 设置 `VLLM_PLUGINS=fl`；BI-V150 比 C500 多一个 `FULL_DECODE_ONLY` graph 参数。两平台分别启动，不把两套参数混用，也不在本机执行。

BI-V150 服务：

```bash
export VLLM_PLUGINS=fl

vllm serve /workspace/MiniCPM5-2B \
  --port 9031 \
  --compilation-config '{"cudagraph_mode": "FULL_DECODE_ONLY"}' \
  --served-model-name minicpm \
  --gpu-memory-utilization 0.85 \
  --max-model-len 131072
```

C500 服务：

```bash
export VLLM_PLUGINS=fl

vllm serve /workspace/MiniCPM5-2B \
  --port 9031 \
  --served-model-name minicpm \
  --gpu-memory-utilization 0.85 \
  --max-model-len 131072
```

接口 smoke 仅验证服务可用，不代替精度或吞吐评测：

```python
import requests
import json

response = requests.post(
    "http://127.0.0.1:9031/v1/chat/completions",
    headers={"Content-Type": "application/json"},
    json={
        "model": "minicpm",
        "messages": [{"role": "user", "content": "introduce llm"}],

print(response.json())
```

完整 Level 3 使用原始采样配置和 105 道题：

```bash
evalscope eval \
  --model minicpm \
  --api-url http://127.0.0.1:9031/v1/chat/completions \
  --api-key EMPTY \
  --eval-type openai_api \
  --datasets math_500 \
  --dataset-args '{"math_500": {"dataset_id": "/workspace/evalscope-datasets/math_500", "subset_list": ["Level 3"]}}' \
  --eval-batch-size 8 \
  --timeout 3600 \
  --generation-config '{"temperature": 1.0, "top_p": 0.95, "max_tokens": 32768}' \
  --work-dir /workspace/evalscope-datasets/level3 \
  --ignore-errors
```

[官方规则] `--ignore-errors` 不等于允许漏题；必须同时检查 105/105 请求是否成功以及最终 accuracy。`temperature=1.0` 下的 seed 与重复判定口径仍待组委会书面答复。

吞吐评测从 `/workspace` 执行原始 wrapper：

```bash
cd /workspace
python3 /workspace/vllm-plugin-FL/benchmarks/benchmark_throughput_serve.py \
  --model /workspace/MiniCPM5-2B \
  --served-model-name minicpm \
  --port 9031 \
  --test-cases '[[4096,1024,64,256],[16384,1024,64,128]]'
```

[源码事实] `benchmark_throughput_serve.py@13eb9be` 固定 `RUNS=4`、`SKIP_FIRST=1`，内部使用 `/v1/completions`、random dataset 和 `--ignore-eos`。四轮均保存，摘要只统计后三轮；`[input_len, output_len, concurrency, num_prompts]` 的两个正式场景、请求成功数和输出行为不得修改。客户端隔离等租赁 C500 的复现细节只见 S02；正式平台仍需按实际镜像核对源码身份和运行路径。
